# v1.0.1

这一版主要是**性能方向的一次尝试**，外加把上一版遗留的文档/CI 问题收尾。

## 新增

### 图标的磁盘缓存

扫描时不再每次都从 APK 里解码图标，而是把 PNG 存到应用缓存目录，下次直接读。

- 缓存键 = `SHA-1(规范路径 + 包名 + versionCode + 文件大小 + mtime)` 取前 16 位。
  这五项任一变化键就变，**不需要解码就能判断缓存是否过期** ——
  所以「新版本换了图标、但文件名没变」不会出现旧图标。
- 存放在 `getCacheDir()/icons`（系统在存储不足时会自己清空该目录）。
- 上限 **500 项 / 8 MB**，超了按「最久未用」淘汰到 70%。

### 设置页新增「清除图标缓存」

显示当前占用（例如「1.1 MB / 115 项」），点一下清空。
缓存本身会自动淘汰，这个入口用于「怀疑图标显示不对」时手动兜底。

## 实测效果（请如实看待）

同一台华为 C8816D / Android 4.3，154 个安装包：

| | 冷扫（清空缓存） | 热扫（缓存已填） |
|---|---|---|
| 解析耗时 | 33.8 s | **30.6 s** |
| 总耗时 | 34.7 s | **31.4 s** |
| 缓存命中 | 0 | **79 / 153（52%）** |

**提速约 9%，不算显著。** 命中率只有一半是因为约四分之一的包本来就没有可提取的图标
（它们在列表里本来也不显示图标），所以永远不会写缓存。

这也说明一件事：**图标解码不是扫描的主要瓶颈**，真正的大头在
`getPackageArchiveInfo` 的资源解析和签名完整性校验上。
下一步的优化方向应该是「整包解析结果缓存」，而不是继续在图标上抠 ——
已经写进 README 的「想继续改进的方向」。

## 其它改动

- 编译目标统一为**字节码 8**（原先在 JDK < 21 时用 7）。旧设置导致
  「本地能过、CI 挂」的诡异编译错误（Java 7 要求匿名内部类捕获的变量显式 `final`）。
- 构建脚本给 `javac` / `d8` 加了堆上限（512 MB），避免在内存紧张的机器上
  以「页面文件不足」的方式直接失败。
- 仓库补充了 Issue 模板、CONTRIBUTING 与 CI 状态徽标（对使用无影响）。
