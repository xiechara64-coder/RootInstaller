# v1.1.0

新增 **APK 管理**：可以删安装包了 —— 单个删，也可以长按多选批量删。
应用平时仍然是安装器，直接打开时就是一份安装包管理器。

## 新增：删除安装包

### 两个入口

| 入口 | 操作 |
|---|---|
| **详情页** | 滚到最底部 →「文件操作」→「删除这个安装包」 |
| **列表多选** | 长按任意一项 → 勾选多个 → 底部「删除」 |

多选模式下底部出现操作栏：**「已选 2 项 · 共 235.0 KB」** + `全选 / 反选 / 删除 / 取消`。
选中项左侧显示实心圆点（未选为空心），行背景变浅蓝。
圆点是用 `shape` 画的 —— 这台 4.3 的 ROM 上有些符号在视图树里存在、屏幕上却画不出来，
所以不用「✓」字形。

### 什么不能删（硬约束）

`/system/`、`/vendor/`、`/cust/`、`/firmware/`、`/data/app/`、`/data/app-lib/`、
`/data/priv-app/`，以及路径里含 `/asec` 的（本机就有 `/storage/sdcard1/asec_apks/*`）。
**只能删你自己放进去的安装包**，拒绝时会给一句人话原因，不静默跳过。

### 删除怎么执行

1. `File.delete()`；
2. 失败（只读 SD 卡/权限不足）且 root 可用 → `su rm -f 'path'`；
3. 都失败 → 明确说「可能是只读的存储卡」，不假装成功；
4. 成功 → 立刻删掉解析缓存 + 发媒体库扫描广播（否则文件管理器还显示它）。

### 删完之后

- 列表**就地移除**并刷新，**不重新扫描**（暖扫也要 13 秒）；
- 从详情页删完返回列表，`onResume` 会剔除"文件已不存在"的项，不留死项；
  在文件管理器里删文件同理；
- 批量删除给汇总：`✓ 已删除 2 个，释放 235.0 KB`；有失败另弹列表说明原因。

## 过程中发现并修掉的两个问题

**1. 缓存失效用错了键（真 bug）**

缓存键里含**文件大小与 mtime**。文件删掉后这两个值变成 0，若在删除**之后**才去算键，
算出的是另一个键，等于"删了个不存在的条目"。

实测表现：删了 3 个包，缓存条目数一个都没减少。改成**先取键、再删文件**。

**2. 列表会留下已删除的死项**

详情页删完返回列表，那一项还在，点开才报"已经不在了"，而且它还能被选进多选、
删除时再报一次失败。现在 `onResume` 会扫一遍 `exists()`（159 次 stat，代价可忽略），
把不存在的项剔掉。

## 实测（华为 C8816D / Android 4.3，156 个安装包）

| 验证 | 结果 |
|---|---|
| 详情页删单个 | 确认框 → 页面切到"这个安装包已经不在了" → 文件真的没了 |
| 列表批量删 2 个 | 底部"已选 2 项 · 共 235.0 KB" → 确认框列出两个文件名 → `✓ 已删除 2 个，释放 235.0 KB` |
| 缓存精确失效 | 放入 2 个测试包：164 → 166 条；删掉后回到 **164** 条（修复前不会减少） |
| 返回列表剔除死项 | 日志出现"列表里有 APK 已经不存在，已从列表移除"，列表从 3 行变 2 行 |
| 系统目录保护 | 规则由离线用例覆盖（system/vendor/cust/data-app/asec 共 9 条路径全部拒绝） |

离线用例从 11 组增加到 **12 组**，新增 `ApkDeleteCheck`：
40 条断言覆盖"能不能删"的路径规则和"选了什么"的多选状态
（反选两次必须回到原状、全选不重复计数、删除后清理选择等）。

## 安全边界

- 删除不可逆 → 两个入口都弹确认框，写清"几个、共多大、无法恢复"；
- 批量确认框列出前 6 个文件名，不是只给一个数字；
- 默认不预选：长按只选中长按的那一项；
- 删的是**安装包文件**，不影响系统里已安装的应用。
