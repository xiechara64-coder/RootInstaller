# v1.0.2

这一版把上一版「图标缓存只快 9%」的教训变成了真正的提速：**整包解析结果缓存**。
暖扫（第二次及以后打开）从 33.6 秒降到 14.1 秒，约 **2.4 倍**。

## 新增：整包解析结果缓存

第一次扫描后，把每个 APK 的「文件自身信息」连同图标一起写入缓存；之后扫描只读缓存。

**缓存内容**：包名、版本、标签、minSdk / targetSdk、安装位置、权限列表、
组件计数、签名方案与证书指纹、完整性结论、CPU 架构、**图标 PNG**。

**刻意不缓存**：与已装版本的对比、权限差异、风险等级 ——
它们取决于「现在装的是什么」，每次必须重算。缓存这些只会让「升级后状态没刷新」。

**缓存键**：`SHA-1(规范路径 + 文件大小 + mtime)`。
读缓存时还没解析，拿不到包名和版本号，所以键只能由文件身份构成 ——
好在 APK 只要被换掉（哪怕改一字节），大小或修改时间几乎必然变，键自然失效。

**为什么带图标**：v1.0.1 把图标单独存了一套缓存，结果两份缓存的键和清理逻辑对不上，
出现「图标写了却每次都要重新解码」。这一版把图标并进解析缓存 ——
一个 APK 一个文件，读一次字段和图标一起拿到，这类问题从根上消失。

**为什么存 `getFilesDir()`**：实测这台设备 `/data` 只剩 28 MB 时，
系统（`installd`）会不停清空 `/data/data/<包>/cache/` —— 缓存放那里刚建好就被删。
现在存在 `files/cache/parse/`，体积 1.4 MB / 154 条，另有 600 项 / 8 MB 上限、
LRU 淘汰和设置页的手动清除。

## 实测（华为 C8816D / Android 4.3，154 个安装包）

| | 冷扫（首次 / 文件变化） | 热扫（缓存命中） |
|---|---|---|
| 解析耗时 | 33.6 s | **13.2 s** |
| 总耗时 | 33.6 s | **14.1 s** |
| 缓存命中 | 0 | **154 / 154（100%）** |

剩下这 13 秒几乎全花在「向系统查询每个包装没装」（`compareWithInstalled`）。
这一项**不能缓存**：用户随时会装/卸，缓存错一次就会显示「未安装」的错误状态。
想再快只能靠系统广播失效，属于「要么做对、要么不做」的事，暂时保持现状。

## 设置页

原来的「清除图标缓存」改为「**清除解析缓存**」，显示当前占用（如「1.4 MB / 154 项」），
点一下清空。旧的独立图标缓存目录会在下次启动时自动清掉，不用手动处理。

## 其它

- 缓存格式带版本号：以后字段有变化时，旧缓存会被自动忽略并覆盖，不会读出脏数据。
- 解析失败的包**不缓存**（失败可能是临时的：文件正被写、内存不足），下次会重试。
- 离线用例从 10 组增加到 **11 组**，新增 `ParseCacheCheck`：编解码往返（含中文、
  null、图标字节）、版本/magic 不符与截断必须返回 null、键随文件变化、
  `capture`/`fill` 字段一致。

## 升级说明

与 v1.0.1 **同签名**，直接覆盖安装即可。首次打开仍会完整扫描一遍（建立缓存），
第二次起变快。
