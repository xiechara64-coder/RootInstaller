# v1.0.3

修一个 v1.0.2 留下的问题：**缓存过的 APK 被删掉之后，它留下的缓存怎么办。**

## 问题

v1.0.2 的缓存键是「路径 + 文件大小 + mtime」。APK 被删/移走之后，
这个键再也不会被查到，对应的缓存文件就一直留着 —— 只能在
「600 项 / 8 MB 上限」被顶满时靠 LRU 顺带淘汰，或者用户手动清空。
设备上只有一百多个包时，这些垃圾可以堆到几 MB。

## 修法：扫描结束后清理孤儿，但**带 7 天宽限期**

规则是**两条同时成立**才删：

1. 本次扫描**没有**用到这个缓存键（说明文件可能没了）；
2. 它**超过 7 天**没被访问过。

**为什么不能「这次没扫到就立刻删」**：因为 SD 卡可能没插或没挂载。
那时卡上所有 APK 都会从扫描结果里消失，立刻删缓存就等于每次拔卡都把缓存清一遍，
插回去又得全部重新解析。宽限期就是为了扛住这种情况。

另外，如果**一个键都没扫到**（存储根本没读出来、或扫描异常），一条都不删。

**怎么知道"多久没被访问"**：命中缓存时会刷新文件 mtime，
所以「最后访问时间」天然等于「这个 APK 最后一次还在扫描结果里的时间」。

## 现在的清理策略是三层

| 层 | 触发 | 作用 |
|---|---|---|
| 上限淘汰 | 600 项 / 8 MB，LRU 降到 70% | 兜住磁盘一直长 |
| 孤儿清理 | 本次没扫到 **且** 超过 7 天没访问 | 处理"APK 已删" |
| 手动清空 | 设置页「清除解析缓存」 | 用户可随时一键清 |

## 验证

- 新增 `CacheSweep`（纯 Java，可离线测）+ `ParseCacheCheck` 第 6 组 **9 条断言**：
  仍在用不删、孤儿超期删、未超期不删、卡没挂载不删、seen 为 null 不删、
  时间在未来不删、长度不一致不抛异常、null 输入不抛异常、混合场景只删该删的。
- 真机（154 个包全在用）：扫描后 154/154 命中，缓存仍是 1.4 MB / 154 项，
  **没有误删**（日志里没有"清理孤儿"这一行）。
- 离线用例仍是 **11 组全通过**。
